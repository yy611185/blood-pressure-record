## 设计系统共同底线（待选定方向后定稿）

- 中文使用 Android 可读无衬线；关键数字使用开口清楚的等宽数字特性。替换现有装饰数字字体。
- 文字初始标尺：页面标题 28sp、分组标题 20sp、正文与表单标签 18sp、辅助文字 16sp、主要读数 44sp、输入值 28sp。最终随原生样张校准。
- 间距 4/8/12/16/24/32dp；页面边距 20dp；组件圆角 12–16dp。主要按钮至少 56dp，触控区至少 48dp，高度随字体增长。
- 品牌色表达操作与选中；正常、偏低、偏高、高风险采用独立状态文字、图标与配色，不能把整张读数卡涂绿来暗示正常。
- 深色模式独立定义背景、表面、文字、边框和状态色，不反转图片或只替换底色。效果图色板只是候选，尚未完成对比度验收。
- 大字优先重排：双列读数可拆行，三列表单可转纵向；不缩字塞入固定盒子。320dp 小屏和 fontScale 1.0/1.3/1.5/2.0 纳入验收。
- 键盘使用系统数值键盘；下一项按高压→低压→脉搏→下一组移动，脉搏可跳过。固定保存区避让 IME，当前输入字段保持可见。

## 后续四阶段

1. 用户选定或调整方向后，建立主题 token、文字标尺、组件样张与深色/大字规则，并写 DESIGN.md。
2. 重做首页、录入、历史、趋势。历史默认日期分组列表，支持日期定位/日历与原始读数详情；趋势摘要置于图前，提供原始及异常记录入口。
3. 将同一系统用于详情、编辑、设置、提醒、数据管理、弹窗、空状态与桌面小部件。提醒和服药能力继续保留，示例首页未穷尽所有条件状态。
4. 验收小屏/大字/深浅色/空与有数据/键盘；回归两组规则、原始读数、平均策略、草稿、编辑与备份。应用视觉统一后再依项目发布流程准备发布。

## 实现前需解决的细节

- 最近升高/降低/波动是待实现的描述逻辑，不以一条下降线直接推断健康改善；比较期、样本不足、两指标方向相反和波动显著需分别表达，阈值与测试另行确定。
- 效果图不是数据规范。B 图首页自动生成的最高/最低值与右侧图表不完全一致，正式界面使用同一数据来源；A 图页脚多余年份不采纳。
- 大字录入不能机械保持效果图三列或强求两组与键盘同时全部可见。先保证当前字段、组状态和保存操作可达。
- B 的完成组折叠须可逆、明确可编辑；数据完整后不能仍显示“再填1组”。这类示例中的细微状态矛盾需要在真实状态驱动实现中消除。
- 历史截图仅用于理解旧界面，不视为现版本验收。尚未进行任何新界面设备验证。
