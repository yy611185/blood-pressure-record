## 1. 信息架构与文案展示层级重构

### 1.1 四类文档的清晰职责边界

当前仓库最大的内容混杂问题在于“用户说明像开发规格书、历史变更日志平铺 6000 字、外部 README 出现重复拼接”。升级后必须建立四类内容的严格边界：

| 文档 / 载体 | 目标读者 | 核心职责 | 严禁出现的内容 |
|---|---|---|---|
| **App 界面微文案** | 普通家庭用户、中老年人（每天高频使用） | 引导动作、反馈结果、即时风险阻断、解释当前视图口径 | 长篇原理课、实现细节、多于 2 行的常驻提示 |
| **应用说明（App 内 `使用指南`）** | 新用户、想弄清分级/隐私/备份的中老年与家属 | 场景化快速上手、看懂三套血压概念、数据安全与隐私全貌、规范测量与免责声明 | 数据库类名（`Room`）、图形参数（`150 DPI`、`PNG`）、工程词（`重建`、`联动十字线`、`Cloudflare` 未解释缩写） |
| **更新说明（App 内）** | 升级后想知道“变好了什么”的普通用户 | 当前版本 + 最近 3 个重要版本的通俗变化摘要；更早 25 个历史版本折叠归档 | 未删内部占位语（`待产品确认`）、CI/构建/R8/依赖升级等纯开发变更 |
| **开发文档（`README.md` / `PRODUCT.md` / `DESIGN.md` / `docs/specs/` / `RELEASE_NOTES.md`）** | 开发者、维护者、开源协作者 | 架构说明、构建发布、医学与格式技术规格、完整工程发版记录 | 不直接照搬为 App 内用户说明 |

### 1.2 四级渐进披露展示模型（Progressive Disclosure）

解决“该提醒的没说清，不该铺开的占满屏”的矛盾，全应用所有说明文案按**阅读频次 × 风险等级**归入四个层级：

| 层级 | 适用场景 | 交互形态 | 字数与排版约束 | 典型归属示例 |
|---|---|---|---|---|
| **L1 常驻可见** | 高频核心动作、医疗急症警示、当前视图数据口径、关键隐私边界 | 卡片副标题、警示横幅、图表内图例、操作前内联提示 | 常驻短句 ≤ 24 字；高风险警示 ≤ 80 字分两句（先急症后复测）；支持大字号自动换行 | 首页高风险红色警示条（`A19`）、周卡虚线来源（`A22`）、趋势达标率口径（`D09`）、医生报告隐私开关说明（`I03`）、更新页防丢提醒（`K07`） |
| **L2 按需展开 / 轻量说明** | 首次需要理解、熟悉后无需占空间的辅助解释 | 标题旁 `ⓘ` 弹窗、默认折叠说明条、副卡可展开详情 | 默认仅显 1 行摘要或小图标；展开后 ≤ 120 字 | “医学分级 vs 个人目标 vs 四色条”区别（`G04/E02`）、趋势“按次 vs 按日”说明、7 日模板“首日计入”口径解释（`I23`）、导入预览高级勾选（`H26`） |
| **L3 场景化弹窗与操作前告知** | 不可逆删除、高风险读数确认、明文导出风险、加密口令警示、权限拒绝兜底 | `AlertDialog` / 底部确认弹窗 / 带撤销的 `Snackbar` | 标题 ≤ 12 字；正文“后果 + 建议动作”≤ 60 字；主按钮明确动词（避免模糊“确定”） | 高风险读数保存确认（`B05`）、永久清空本地数据二次勾选（`H28`）、删除药品连带删除打卡记录告知（`F11`）、明文导出风险确认（`H07`）、口令遗失不可找回（`H09`） |
| **L4 统一使用指南与历史归档** | 系统性学习、完整医学分级标准、完整隐私数据流、测量规范、历史版本追溯 | 独立一级入口「使用指南与更新」（不再藏于折叠“数据”区）+ 历史版本默认折叠区 | 按 6 个用户场景分章，每章 3–5 条短段落；历史版本默认展示近 4 个版本，其余折叠 | 2024 指南 5 档分级 + 135/85 家庭参考值（`J07`）、完整联网与日历隐私说明（`J06/J04`）、规范家庭测量 5 步法（`J08`）、25 个更早历史版本（`K13`） |

## 2. 全局 UX Writing 规范与术语体系

### 2.1 产品声音（Brand Voice）与人设边界

- **应用定位**：家庭里的安静、靠谱、懂分寸的健康记录本。
- **核心气质**：**温暖亲切 · 简洁直白 · 专业克制 · 尊重长辈**。
- **小压（Buddy）角色边界**：
  - 小压是**习惯陪伴者**，负责问候、鼓励连续记录、温和提醒常规测量前静坐休息。
  - **严格禁区**：当出现高风险读数（`≥180` 或 `≥120 mmHg`）、血压偏低（`<90` 或 `<60 mmHg`）、2–3 级显著升高时，小压必须**立即退出卖萌口吻**（禁用“好吗？”“～”“哦”“啦”），切换为沉稳、清晰的引导语；**永远不给出具象医疗干预指令**（如“多喝点水”“马上吃药”“加服半片”）。

### 2.2 六大场景语气矩阵（Tone Matrix）

| 场景类型 | 推荐语气 | 禁用表达 | 正例 | 反例 |
|---|---|---|---|---|
| **1. 日常陪伴（问候/达标/连续记录）** | 温和、鼓励、自然，不夸张、不幼龄化 | 过多波浪号 `～`、把用户当小孩（“很听话”“真乖”） | `本次读数在正常范围，继续保持。` / `已经连续记录 7 天，继续保持！` | `漂亮！今天的血压很听话 ✓`（旧记录也喊“今天”） |
| **2. 一般操作与反馈（保存/搜索/切换）** | 简洁、明确、给预期 | 技术名词、无动作指向的“确定” | `已保存 124/78` + `再改改` / `正在生成报告…` | `操作成功` / `重建后保持位置` |
| **3. 校验与输入错误** | 客观指出错在哪里 + 怎么改，不责备 | “非法输入”“校验失败”“参数异常” | `高压应大于低压，请检查后重试` / `口令至少 8 位` | `输入非法` / `非法血压值` |
| **4. 不可逆 / 高风险数据操作** | 冷静、直白交代真实后果、给出逃生退路 | 轻描淡写、隐瞒级联删除后果 | `将删除「氨氯地平」及它的全部服药打卡记录，且会同步移除已写入的日历提醒。` | `将删除「氨氯地平」及其全部服药时间。`（隐瞒历史打卡会一起被删） |
| **5. 医疗安全警示** | 严肃、清晰、先急症红旗后复测、杜绝模糊逻辑 | “大概”“左右”“180/120 以上”、卖萌商量口吻 | `本次有读数达到收缩压 ≥180 或舒张压 ≥120 mmHg。如伴有胸痛、呼吸困难、剧烈头痛、言语不清、一侧肢体麻木无力或视物模糊，请立即就医或拨打 120，勿自行加药。` | `这次读数很高，先休息一下，再复测一次好吗？` |
| **6. 专业医生报告（PDF / 摘要图）** | 客观、中性、医学术语规范、披露统计口径边界 | 情绪化鼓励语、口语缩写“高压/低压”、未声明边界的缩写 | `收缩压 / 舒张压 (mmHg)` / `统计口径：首日计入（未剔除首日）` / `高于或等于参考线（≥140 或 ≥90）` | `高于参考线（140/90）`（与代码 `>=` 逻辑不符） |

### 2.3 统一术语词典（Terminology Glossary）

| 概念 | 应用内主界面推荐用词 | 医生报告 / 医学说明用词 | 禁止 / 淘汰混用词 | 备注 |
|---|---|---|---|---|
| **应用名称** | `家庭血压记录` | `家庭血压记录` | `血压追踪`、`血压记录`（除非历史日历匹配常量） | `MedicationCalendarSync.EVENT_DESCRIPTION` 含历史匹配键，暂不直接修改 |
| **第二人称** | 统一用 `你` | 第三人称或中性无主语（`患者`/`本周期`） | 在应用内局部混用 `您`（`E13/K02/K11`） | 温暖平实、像家人沟通；免责与报告保持客观无主语 |
| **收缩压 / 舒张压** | 录入与日常视图统一用 **`高压（收缩压）` / `低压（舒张压）`**（首次或标签带括号，紧凑格用 **`高压` / `低压`**） | 严格用 **`收缩压` / `舒张压`** | 同一卡片上半截写“高压”、下半截写“收缩压” | 照顾老人日常认知，同时在给医生看的报告保持医学严谨 |
| **单次记录与多组读数** | 单条记录称 **`本次测量`** 或 **`这条记录`**；内部各行称 **`第 1 组`、`共 3 组读数`** | `记录次数（次）`、`单次原始读数` | 把 1 条记录里的 3 组读数混称为 `3 次测量`（`C08`） | 区分“测一次（含 2–3 组读数）”与“一天测了 2 次” |
| **服药打卡动作与状态** | 按钮：`打卡` / `已打卡`（或 `记为已服`）；状态：`今日已打卡`、`待打卡` | `已记录打卡次数（次）` | `吃了`、`已服用`、`今天的药都吃过啦` | 明确 App 只记录用户“打卡”，不虚构证实实际吞服 |
| **四色条 vs 目标值 vs 医学分级** | ① **`医学分级`**（固定 6 档）<br>② **`个人达标值`**（个人参考上限）<br>③ **`首页四色条`**（视觉色带区间） | 报告仅使用 `诊室血压分级` 与 `诊室参考线 (140/90)` | 将四色条称为“目标范围”或“医学标准” | 彻底消除三套参考线混淆 |
| **时段统计名称** | 统一用 **`早间平均` / `晚间平均` / `日间平均` / `夜间平均`** | 统一用 `早间平均` / `晚间平均` | 混用 `早晨均值` / `早间平均`（`D03/D04`） | 保持趋势页与 PDF 报告完全同词 |
| **恢复 / 复位** | 图表视野：`复位视野`；数据备份：`恢复备份` | — | 两处均简写为 `恢复`（`D21`） | 防止动词重名 |
| **高风险阈值描述** | **`收缩压 ≥180 或舒张压 ≥120 mmHg`** | `≥180/120 mmHg（收缩压 ≥180 或舒张压 ≥120）` | `180/120 以上`、`≥180/120`（无“或”字易被误读为“且”） | 单轴达标即触发，必须写明“或” |
| **备份文件格式** | `加密备份（.bpx）`、`Excel 表格（.xlsx）` | — | `明文 xlsx`、`BPX 文件`（无中文解释） | 中文名称在前，扩展名括号补充 |
| **提醒页面名称** | 统一称 **`提醒与服药`**（一级标题与入口同名） | — | 入口叫“提醒与服药”、页内叫“提醒中心”或“提醒设置” | 保持路径记忆一致 |

### 2.4 标点、数字空格与短/长版规则

1. **中英文/数字间距**：中文与阿拉伯数字、单位、英文之间留 1 个半角空格（例如：`近 7 天`、`静坐休息 5 分钟`、`收缩压 ≥180 或舒张压 ≥120 mmHg`），紧凑标签或圆角徽章可酌情紧凑（如 `7天`、`120/80`）。
2. **范围连接符**：统一使用中文短横/一字线或半角 en-dash `–`（如 `120–139`、`05:00–11:59`），不再混用 `-`、`~`、`至`（正文口语可用 `5 到 7 天` 或 `5–7 天`）。
3. **标点克制**：
   - 标题、按钮、标签、列表短项（无完整主谓句）**末尾不加句号**。
   - 完整说明句、警告句、对话框正文**末尾加中文句号**。
   - 严禁在医疗提醒、错误提示中使用波浪号 `～` 或感叹号堆砌；日常鼓励最多使用 1 个感叹号。
4. **短版 / 长版双规适配（适老化核心）**：
   - 凡可能出现在 320dp 窄屏、胶囊标签、小部件或 2.0× 大字模式下的按钮/状态文案，**必须 ≤ 6 个汉字**（如 `已打卡`、`再改改`、`复位视野`、`去设置`）。
   - 说明文字优先写成**“核心结论句（≤18 字）+ 补充说明句”**结构，确保老人只看前半句也能抓到重点。

### 2.5 后续维护与发版文案检查规则

后续每次 PR 涉及界面文案、新功能或发版时，执行以下最小检查清单：
1. **同步更新清单**：新增面向用户功能时，同步更新 `AppInfoContent.featureSections`（使用指南）、`AppReleaseNotes`（当前版本用户向摘要）与 `RELEASE_NOTES.md`。
2. **文案三不准**：① 不把代码字段名/异常类名（`record_id`、`KDF`、`HTTP`、`XML`）直接暴露在 Toast/Dialog；② 不新增绝对化隐私承诺（“绝不联网”“只在本机”）而不交代更新/日历/导出边界；③ 不由小压输出未经医学指南背书的具象干预指令（如饮水、加药）。
3. **测试联动**：修改或清理文案及死代码时，同步核对现有单测与仪器测试（特别是 `AppReleaseNotesTest.kt`、`BpRangeBarTest.kt`、`ReportViewModelTest.kt`、`SettingsNavigationRouteTest.kt`）。

## 3. 页面级体验升级与最小必要 UI/UX 调整方案

> **约束说明**：以下调整全部遵循**“文案重构为主 + 最小必要布局微调”**原则，不改现有 Warm Paper 设计系统、不改数据库表结构、不改医学判定公式。

### 3.1 首页（`DashboardScreen` + `WeekCard` + `BpRangeBar`）

**核心问题**：小压旧记录仍喊“今天”、低血压劝喝水、高风险态语气失当、服药无剂量时出现孤立中点 `08:00 · `、四色条与周卡虚线来源不清。

**升级方案**：
1. **小压文案按“是否今日记录 × 医学分级”双维度分流**（`A07–A13`）：
   - 仅当 `latest.measuredAt` 属于今天时，称“本次/今天”；若为更早日期，明确点出日期（如 `上次（M月d日）血压正常，今天记得量一量。`），防止老人误以为今日已测。
   - `HIGH_RISK` 与 `LOW` 分支彻底去除卖萌词，执行 §2.2 严肃安全文案。
   - 当关闭“显示小压”开关时，空态气泡不再自称“我是小压！”。
2. **高风险警示条重构**（`A19`）：
   - 明确写清 `收缩压 ≥180 或舒张压 ≥120 mmHg`；**先列急症红旗症状与立即就医/120 及勿自行加药**，再写无不适时静坐休息 5–10 分钟后复测。
3. **首页四色条与周卡虚线去歧义**（`A21/A22`）：
   - 周卡图例虚线标注为 `虚线参考 ${normalSystolicCut}/${normalDiastolicCut}（四色条正常上界）`（窄屏/大字自动折行显示短版 `虚线 ${normalSystolicCut}/${normalDiastolicCut}`），避免与趋势页 140/90 诊室参考线混淆。
   - 清理未使用的 `bp_range_edit_hint` 字符串资源，或在四色条右侧增加轻量 `ⓘ / 调整` 入口（列入决策清单 `DEC-05`）。
4. **修复服药行视觉瑕疵与统一“打卡”术语**（`A04/A27/A33/A34`）：
   - 当 `dosage` 为空时，不渲染尾随中点 ` · `（仅显示 `08:00`）。
   - 按钮从 `吃了` 统一为 `打卡`（已完成状态显示 `已打卡`）。

### 3.2 血压录入与编辑（`RecordScreen` + `SessionFormComponents`）

**核心问题**：高风险弹窗“仍要保存”容易劝退用户保存真实高值记录给医生看；存在两处已废弃死组件（`B14 SessionCompletedDialog`、`B26 SessionSupplementFields`）；`+ 再测一组` 按钮语义与“高压/收缩压”标签略混杂。

**升级方案**：
1. **高风险保存确认弹窗重构**（`B05/B06`）：
   - 标题：`检测到高风险读数`
   - 正文：`本次记录包含收缩压 ≥180 或舒张压 ≥120 mmHg 的读数。如伴有胸痛、呼吸困难、剧烈头痛、言语不清、一侧肢体麻木无力或视物模糊等不适，请立即就医或拨打 120，切勿自行加药。若无不适，请静坐休息 5–10 分钟后复测。`
   - 按钮：主按钮改为 **`保存记录（供医生参考）`**（消除“仍要保存”的责备/劝退感，鼓励保留真实高值供就诊），次按钮 **`返回检查数值`**（帮助排查是不是手滑多打了一个 0，如把 128 打成 188）。
2. **统一表单字段与增组提示**（`B02/B08/B10/B15`）：

#### 三、看懂血压分级、四色条与个人达标值
- **医学血压分级（诊室标准）**：应用内单次分级参考《中国高血压防治指南（2024年修订版）》成人诊室血压标准（单位 mmHg）：
  正常血压：收缩压 <120 **且** 舒张压 <80；
  正常高值：收缩压 120–139 **和/或** 舒张压 80–89；
  1 级高血压：收缩压 140–159 **和/或** 舒张压 90–99；
  2 级高血压：收缩压 160–179 **和/或** 舒张压 100–109；
  3 级高血压：收缩压 ≥180 **和/或** 舒张压 ≥110。
  当收缩压与舒张压分属不同级别时，按较高级别归类。
- **家庭自测参考区别**：通常情况下，居家安静自测的血压略低于医院诊室测量值。依据《中国高血压防治指南（2024年修订版）》及《2019中国家庭血压监测指南》，连续 5–7 天规范家庭自测平均血压 **≥135/85 mmHg** 即提示血压升高，具体诊断请以医生综合判断为准。
- **血压偏低与高风险提示**：当收缩压 <90 或舒张压 <60 mmHg（且另一项未升高）时，会显示“血压偏低”（为本应用附加提示，不属于上述指南分级）。当任一组原始读数或平均值达到 **收缩压 ≥180 或舒张压 ≥120 mmHg** 时，会触发独立于分级的“高风险读数”提示；如伴有胸痛、呼吸困难、剧烈头痛、言语不清、一侧肢体麻木无力或视物模糊等症状，请立即就医或拨打 120，切勿自行加药。
- **分清应用里的三套参考**：
  1）**医学分级**：固定采用上述国家指南标准，不可自定义；
  2）**个人达标值**：可在「我的 → 个人资料」中按医嘱设定（默认 <135/85 mmHg），仅用于计算日历达标天数和趋势达标率；
  3）**首页四色条**：可在「我的 → 首页四色条区间」自行调整（默认为直观参考区间），仅影响首页色条位置和周卡参考虚线，不改变医学分级与趋势统计。

#### 四、数据备份与医生报告
- **导出备份防丢失**：本应用已关闭手机系统的自动云备份，**换机、刷机或卸载应用前请务必先导出备份**，否则未导出的本地记录会随卸载永久丢失。
- **加密备份与 Excel 表格**：在「我的 → 数据管理」支持两种导出方式——推荐使用**口令加密备份（.bpx）**以保护健康隐私，口令由你自己设置且不会保存，请务必牢记（遗失口令无法找回数据）；也可导出**明文 Excel 表格（.xlsx）**便于在电脑查看或打印，分享前请留意隐私保护。记录数量较多时会自动分卷保存，恢复时按提示从第 1 卷起依次导入即可。
- **安全恢复与清空**：恢复备份前会先展示内容预览，可自主勾选需要恢复的范围（血压记录、个人资料、显示设置、提醒或用药），未勾选的项目保持原样。你也可以在数据管理中清空本地数据，清空前需二次确认，操作不可撤销。
- **生成医生报告**：在「数据管理 → 生成医生报告」可选择近 7、30、90 天或自定义周期（最长 365 天）在本机生成复诊 PDF 报告，支持预览、分享、保存和系统打印，也可另存摘要图片方便快速发送（注意：摘要图片仅包含第 1 页摘要，完整逐日明细请发送 PDF）。
- **报告隐私与统计口径**：进入报告页时「姓名与年龄」默认关闭且不记住上次选择，你也可自主隐藏备注或药品。若选择「7 日家庭监测模板」，统计口径为**首日计入（未剔除首日）**、全部时段参与统计、有记录日即为有效日；有效天数不足 3 天时会提示统计仅供参考。报告内分级与参考线采用诊室标准（140/90 mmHg），用药模块仅统计当前保留药品的打卡次数，无法还原历史漏服或调药记录。

#### 五、数据安全、隐私与软件更新
- **健康记录默认留在手机本机**：应用无需注册账号，也不提供云端同步服务器；血压、脉搏、备注、用药和个人资料默认只保存在你的手机本地。
- **三项你应知晓的数据边界**：
  1）**软件更新检查**：应用默认开启自动检查更新（成功后 24 小时内不重复请求，可随时关闭）。检查更新仅访问更新服务获取版本号与更新日志，**不会读取或上传任何健康记录、个人资料或备份文件**；但网络服务及内容分发服务（Cloudflare）会按常规网络通信记录访问 IP、时间及基本请求日志。
  2）**系统日历同步（可选）**：仅在你手动开启后，才会将服药日程写入你指定的系统日历；该日历可能随手机账号云同步或共享给他人。为保护隐私，日程默认仅显示「服药提醒」，不包含药名和剂量（除非你手动开启显示详情）。
  3）**主动导出、分享与桌面小部件**：你主动导出的备份文件、医生报告或分享给微信/他人的文件，以及添加到手机桌面的小部件，其可见性与后续去向由你与对应系统/接收方控制。
- **安全升级指南**：发现新版本后，点击按钮会跳转手机浏览器下载安装包（APK），也提供备用下载页（GitHub Releases）。下载完成后请直接打开并按系统提示**覆盖安装，切勿先卸载旧版，以免丢失本地记录**。即使暂不升级，也完全不影响离线记录血压、查看历史和导出备份。

#### 六、规范测量建议与医疗免责声明
- **家庭规范测量要点**（参考《2019中国家庭血压监测指南》）：
  1）测量前 30 分钟内避免剧烈运动、吸烟、饮酒及饮用咖啡或浓茶，测量前先排空膀胱；
  2）安静端坐于有靠背的椅子上休息至少 5 分钟，双脚平放地面不跷二郎腿；
  3）上臂袖带绑于上臂并与心脏保持同一高度，测量过程中保持放松、不要说话；
  4）建议每天早晚固定时段测量（如早晨起床后 1 小时内、服药和早餐前；晚间睡前），每次连续测 2–3 组，每组间隔 1–2 分钟；血压长期稳定者可遵医嘱调整测量频率。
- **医疗免责声明**：本应用仅用于家庭日常健康记录与趋势观察，不提供医疗诊断、治疗方案或处方建议。应用内的血压分级、图表、提醒及导出的报告均仅供参考，不能替代专业医生的当面评估。请勿仅凭本应用结果自行加药、减药或停药；如持续偏高、偏低或出现任何身体不适，请及时就医。

待维护者在 [UX_WRITING_DECISIONS.md](UX_WRITING_DECISIONS.md) 逐项批复后，建议按三个清晰批次落地，每批次独立可测、可回滚：

#### Phase 0：安全、隐私与医学事实必改项（全部 P0，预计改动最小、收益最高）
- **核心改动**：
  1. 首页小压旧记录时间分流 + 移除低血压喝水指令 + 高风险态严肃文案 + 高风险警示条（≥180 或 ≥120、先急症后复测、勿自行加药）。
  2. 录入页高风险弹窗文案与主按钮（`保存记录（供医生参考）` / `返回检查数值`）。
  3. 趋势页达标率比较去掉“更稳了”混淆。
  4. 高风险开关副标题补全边界与单位；设置页底部隐私宣言如实交代更新/日历例外。
  5. 删除药品确认弹窗补全“同时删除历史打卡记录”告知。
  6. PDF 表格图例由 `高于参考线（140/90）` 修正为 `达到或超过诊室参考线（≥140 或 ≥90 mmHg）`；7 日模板前置“首日计入（未剔除首日）”。
  7. （若批准 `FUNC-01`）`ReminderReceiver.kt` 增补 `VISIBILITY_PRIVATE` 锁屏隐私保护。
  8. （若批准 `DEC-02`）数据管理页主次按钮互换（加密备份为主按钮）。
  9. 清理 `README.md` 末尾 230–309 行严重重复残段。

### 6.2 验收标准（含自动化与真机核验清单）

#### A. 文案与合规验收
- [ ] 全应用 `src/main` 搜索无 `多喝点水`、`今天的血压很听话`、`更稳了`、`待产品确认`、`Room 数据库`、`150 DPI`、`重建后保持`、`应用内闹钟`、`错误 0 条`、`高于参考线（140/90）` 等已淘汰文案。
- [ ] 医疗安全复核：录入 `180/85`（仅收缩压达标）和 `130/120`（仅舒张压达标）时，保存弹窗与首页警示条均准确提示 `收缩压 ≥180 或舒张压 ≥120 mmHg` 且先列急症红旗症状与立即就医、勿自行加药。
- [ ] 隐私一致性复核：锁屏状态收到服药通知不暴露药名与剂量（若启用 `FUNC-01`）；未授权日历前不触发日历写入；医生报告每次重进“姓名与年龄”均重置为关闭。
- [ ] 单测与构建通过：`AppReleaseNotesTest`、`SettingsNavigationRouteTest` 及全部相关 ViewModel / Report 测试通过。

#### B. 真机与适老化 / 无障碍专项验收（**不可仅靠静态审查替代**）
- [ ] **320dp 窄屏 + 2.0× 大字号**：首页高风险警示条、周卡图例、录入页按钮、数据管理页主次按钮、更新弹窗按钮均不截断、不重叠、不把确认/退出按钮挤出可视区。
- [ ] **深色 / 浅色双主题**：高风险红条、偏低色块、桌面小部件、PDF 预览与历史日历达标标识对比度清晰可读。
- [ ] **横屏全屏趋势图**：所有控制按钮可见，双击复位视野与返回竖屏后状态正常。
- [ ] **TalkBack 无障碍实测**：首页最近记录、服药打卡行、历史日历单元格、趋势十字线选中节点、数据管理折叠项与更新弹窗朗读完整、无歧义、不含裸英文缩写。
- [ ] **Android 14+ 多厂商真机验证**：精确闹钟权限拒签兜底提示、Doze 模式延迟提醒表现、外部浏览器下载与覆盖安装路径、系统打印服务与微信/文件管理器分享流程正常。
