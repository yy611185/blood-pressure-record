# 血压记录 Android 项目审计

2026-11-24 · main · 0b6a040 · 2.3.9（50）

建议下一版本先修复服药通知、用药备份往返和日历隐私三项问题。前两项会在正常使用路径中产生错误提醒或重复药品，第三项的影响取决于用户授权后实际选中的日历。以下为代码审查发现，设备端未逐项复现。

除表中问题外，以下操作也会产生可观察的差异。

- **P2 延迟中的提醒可能被跳过。** 未授予精确闹钟权限时，系统可能在预定时间之后才交付提醒。此时冷启动或另一条通知送达会全量重排，同一 PendingIntent 被替换为次日闹钟。核查 BloodPressureApplication.kt:30、ReminderScheduler.kt:147、MedicationReminders.kt:43、61 和 ReminderReceiver.kt:46、73。验收时应保留一条已到期但尚未送达的提醒，触发重排，确认当天恰好收到一次。
- **P3 旧库迁移会误判部分测量的平均策略。** 从 v6 升到 v7 时，SQL 的 NULL 比较会漏掉本应标记为丢弃首组的记录。提取 AppDatabase.kt:137–160 的 SQL 在内存 SQLite 执行：两组均为 120/80，仅首组有脉搏 75，原代表值脉搏为空，迁移后实际写成 ALL。后续编辑可能改变代表值。应采用能处理 NULL 的比较，并将此例纳入迁移测试。

- **P2 恢复备份可能漏显高风险记录。** BackupImportService.kt:453–469 在备份代表值有效时优先采用表内的 high_alert。如果旧文件或手工编辑的文件写入 false，即使原始读数触发当前规则，历史详情和趋势计数也沿用 false。应保留历史代表值，并检测、提示或修正标记与原始读数之间的冲突。

- **P2 清空后仍可从应用导出清空前的数据。** 准备备份后在保存对话框选择“稍后继续”，清空数据，再点击导出，会继续旧的 pendingExportPlan。SettingsViewModel.kt:538–548、642、667–669、838–850 保留了快照和待用口令。清空成功时应撤销旧导出，并用单卷及多卷流程验证。
- **P2 换机恢复遗漏服药提醒总开关。** 旧机关闭服药提醒后，同时恢复提醒设置和用药数据，新机会采用默认开启值并重排闹钟；取得通知权限后可能再次提醒。BackupExportService.kt:247–265、AppSettingsStore.kt:60、200–213、DefaultSettingsRepository.kt:367–369。应将此开关纳入往返，并为缺少字段的旧备份保留可预期的行为。
