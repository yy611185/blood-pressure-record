# 医生报告 PDF · 阶段 1

本阶段提供固定近 30 天的本地 A4 PDF：摘要、逐日明细及必要的补充页。报告生成前每次询问姓名与年龄，默认隐藏；用户检查预览后分享或保存。没有记录时不生成，少于 3 个有效日使用固定统计不足文案。当前没有打印、自定义周期、备注与药品开关或摘要图片保存。

## 统计与数据边界

- 统计周期含今天，覆盖 30 个本地自然日；进入导出流程时捕获当前时区，以 epoch 半开区间查询记录。领域模型支持最多 365 天，为后续周期选择留出边界，阶段 1 界面固定 30 天。
- 期间平均基于各次记录已保存的代表值等权计算，脉搏只统计有值的记录；不根据原始组重新计算或覆盖历史代表值。日均值复用现有平均和分级计算器。
- 早晨为 05:00–11:59，晚间为 18:00–23:59，与 App 现有统计一致。同日多次测量按时间逐次排列；其他时段参与总体和每日统计，并进入补充明细。
- 现有场景文本不能可靠区分家测与诊室，不根据文本猜测。报告注明“未区分测量场景，分级与参考线采用诊室标准”，参考线为集中配置的 140/90。
- 仅列当前数据库保留的药品信息和周期内服药打卡次数，以打卡已存 `epochDay` 归日。已删除药品的打卡不能恢复，历史计划、漏服与调药不能推算，不生成依从率或调药标记。
- 逐日表格每页最多 30 个物理行。同日多次测量可能增加行数；长备注与额外药品信息进入补充页。所有页面先由纯 Kotlin Planner 计划，总页数包含补充页。

## 实现与输出

主要文件分布：

- `domain/report/`：`ReportPeriod`、`ReportOptions`、`BpReport`、`ReportBuilder`、`ReportLayoutPlanner`、`ReportPolicy`；无 Android、Room 或 UI 类型。
- `domain/calculator/SessionStatisticsCalculator.kt`：供趋势统计和报告共享的平均与早晚判断。
- `data/repository/ReportRepository.kt`、`DefaultReportRepository.kt` 及 `MedicationDao`：短事务读取周期内一致快照，退出事务后计算与绘制。
- `export/report/`：`ReportTheme` 集中尺寸、颜色及参考线；`PdfReportRenderer` 使用 `PdfDocument` 与系统无衬线字体；`ReportShare`、`ReportCache` 处理平台输出与临时文件。
- `ui/report/`：`ReportViewModel`、`ReportGeneration`、`ReportOptionsScreen`、`ReportPreviewScreen`；数据管理和导航接入入口。
- Manifest 与 `reports_file_paths.xml`：独立报告 Provider 只暴露 `cacheDir/reports/`。
- `src/test/.../domain/report/`、`src/test/.../ui/report/` 和报告仪器测试：统计、分页、流程和渲染验证。

物理 PDF 页面为 595×842 pt，内部布局保持模板小数坐标；整数页面尺寸来自 `PdfDocument.PageInfo.Builder` API 的限制。每个导出使用独立缓存子目录，文件名为 `血压报告_起始日期-结束日期.pdf`，不含姓名。分享只授予临时 URI 读取权限；保存使用 SAF `CreateDocument`，不申请存储权限。

保存使用用户预览过的同一份 PDF，不重新读取数据库或生成新文件。未分享的取消、失败文件及时删除；已分享文件保留 24 小时，下次进入报告时清理过期文件。分享目标选择回调不代表接收方已经读取完成。

报告生成不请求网络，不嵌入联网资源，不输出健康数据或异常原文到日志，不改 Room v9、备份 v6、已有统计或版本号。应用已有软件更新联网能力与报告数据流程分开。
