# UI / UX 审查 · 2026-09-09

总体结论：现有奶油色、陶土橙、鼠尾草绿的组合协调，适合家庭记录的温和定位，值得保留。优先改善文字可读性、深色主题、状态表达和录入效率；视觉上减少大面积沙色卡片、重复提示和不必要的层层圆角。

## 审查范围与证据

- 源码基线：`eb192c3`，Jetpack Compose，项目版本 1.8.3。
- 真机：PHB110，1440 × 3216，显示密度 override 640（约 360dp 宽）；系统原始 font_scale 0.9，另检查 1.5。应用还有自身大字倍率，系统值不是最终字号倍率。
- 检查包：`com.yang.bloodpressure`，versionName 1.8.3 / versionCode 30。手机另有旧包 `com.example.bloodpressurerecord` 1.8.1，不作为本次结论依据。未以二进制哈希验证安装包与当前源码完全一致。
- 真机浏览：首页、录入及底部、历史日历、趋势、设置、提醒设置、数据管理；检查深色历史页、大字历史与录入页。
- 当前应用无测量记录，因此有数据的首页、历史详情、曲线与异常结果属于静态分析，未冒充真机复现。未写入测量、药品、备份，也未执行删除。未做 TalkBack 完整巡检。
- 已恢复 font_scale 0.9 和 night mode `custom_schedule`，回到首页。未改应用源码。9 月 6 日旧截图仅作背景参考，不作为本次复现证据。

## 优先修复

### 1. P1 · 深色主题选中标签难以辨认【实机复现】

历史页选中“日历”使用固定深棕色 `Terracotta800`，背景却随深色主题变暗，文字/背景 `#643312 / #2E2B25` 对比度只有 **1.36:1**。越是当前选中的项目越不清楚。

证据：[深色历史页](09-history-dark.png)。位置：[HistoryScreen.kt:404](../../app/src/main/java/com/example/bloodpressurerecord/ui/history/HistoryScreen.kt#L404)。首页读数也固定使用 Terracotta700，在深色卡片上约 **2.07:1**，但本次无记录，未实测读数状态。

建议：选中项使用主题化 `onPrimaryContainer / primaryContainer` 配对；读数、药品时间等都改用适配亮暗模式的语义色。不要仅把全局 primary 调亮，固定颜色的调用点不会随之修复。

### 2. P2 · 次要文字过淡，核心字段名称过小【实机观察 + 色值计算】

录入字段名称只有 11sp，且与说明文字、设置副标题一样使用 `#82796A`。该色在沙色卡片 `#EBDDC5` 上为 **3.21:1**，在页面背景上为 **3.61:1**。高压、低压是关键字段，不应按弱提示处理。

证据：[录入页](03-form.png)、[设置](07-settings.png)。位置：`ui/common/SessionFormComponents.kt:319–337`、`ui/theme/Color.kt`、`ui/theme/Theme.kt`。

建议：核心标签至少采用 14sp，并优先考虑“高压 / 低压 / 脉搏”的短标签，保留完整无障碍名称；普通说明采用现有 `WarmTextBody #645C50`，在原卡片上约 **4.92:1**。不要把禁用文字标准用于可用的字段标签。

浅色实心选项的白字/陶土橙只有 **3.40:1**，对 13sp 的选中 chip 不足；原色可以保留作装饰，大字按钮单独判断，不能把所有橙色按钮一概判为不合格。小字实心选项可使用更深的 Terracotta700，配 OnTerracotta 约 **6.42:1**。

### 3. P2 · 大字模式日历图例丢失【实机复现】

font_scale 1.5 时，固定单行的四个图例互相挤压：“含备注”断行，“选中”消失。正常字号下四项可见。

证据：[普通字号](05-history.png)、[大字浅色](11-history-large-light.png)、[大字深色](10-history-large.png)。位置：`ui/history/HistoryScreen.kt:672`。

建议：使用 FlowRow 或两列布局，让每个“色点 + 标签”作为整体换行；不要缩字补救。首页大数字仍是 54sp 单行加单位、今日概览也是连续 Row，应补测三位数读数和大字体；这部分目前是代码风险，不能称为已复现溢出。

### 4. P2 · 日历图例描述与数据条件不一致【代码确认】

橙色日期由 `containsHighRisk` 决定，图例却写“含偏高读数”。用户可能据此把没有橙色标记的日期理解为没有偏高记录。备注用红点，高风险用浅橙，也会让视觉优先级颠倒。

位置：`ui/history/HistoryViewModel.kt:120`、`ui/history/HistoryScreen.kt:613,678`；图例真机可见于 [历史页](05-history.png)，有记录日期未实测。

建议：图例与判断条件统一为“含高风险读数”；高风险用一致的红色与警示图形，备注改为中性色的小文档标记。若另需表示一般偏高，增加独立判断与图例，而不是复用高风险字段。

### 5. P2 · 结果卡片的颜色和状态表达不足【代码确认】

`AverageResultCard` 不论正常、偏低或偏高，都使用绿色 `secondaryContainer`；具体分类只转成一句口语化评语。首页又将多个偏高等级压缩成同一句提示，用户不容易跨页面对应结果。

位置：`ui/record/AddMeasurementScreen.kt:375–456`、`ui/home/DashboardScreen.kt:277`。

建议：数值区用中性表面，附明确分类文本与状态图标，复用现有 StatusChip；绿色只用于明确正常状态。数值、分类与补充说明分层呈现。分类阈值不属于本次视觉审查范围。

### 6. P2 · 保存入口离录入区太远【实机观察 + 代码确认】

录入两组后，用户仍需越过场景、症状、11 个影响因素及备注，才能找到保存按钮。未填完整时，原因也只在末尾显示。大字模式改为纵向输入后，距离进一步增加。

证据：[录入首屏](03-form.png)、[录入底部](04-form-bottom.png)、[大字录入](13-form-large.png)。位置：`ui/record/AddMeasurementScreen.kt:286`，`embedded = true`。

建议：把保存与校验摘要放到 Scaffold 固定底栏，处理键盘避让；症状维持清晰可见，其他补充项按需展开。错误同时显示在对应字段或组标题下。不要把表单所有补充信息都强迫用户逐段经过。

### 7. P2 · 删除药品没有恢复入口【代码确认，未执行删除】

药品列表“删除”直接调用 ViewModel 和 repository；该调用路径没有确认弹窗或撤销。它与“编辑”并排，误触会直接删除药品并刷新提醒。

位置：`ui/settings/SettingsSubpages.kt:314`、`ui/settings/SettingsViewModel.kt:deleteMedication`。

建议：提供包含药名的确认，或实现真正可恢复药品及关联时间的撤销；将删除动作放进次级菜单，降低与编辑的误触概率。

## 设计与流程优化

### 8. 首屏空状态占用过多空间【实机观察】

首页“还没有血压记录”卡片已有入口，外面又有主按钮，下方今日概览再说一次没有记录。趋势页也有绿色“没有记录”提示和内层“暂无数据”卡片，且空数据时仍显示整套曲线切换。

证据：[首页](02-home.png)、[趋势](06-trend.png)。建议：首页保留一句说明和一个明确的“记一次血压”，弱化重复空状态；趋势空状态集中成一个区域，提供可直接进入录入的按钮。有数据时把时间范围放在摘要之前，曲线靠前，统计范围放到后面或紧凑布局。

### 9. 颜色协调，但层级偏平、圆角容器偏多【设计判断】

同一沙色大卡片覆盖了空状态、设置入口、数据说明和图表，视觉重量接近；趋势页还有“卡片套卡片”。圆角和柔和阴影可以保留，但不必让所有内容都占一张大卡片。

建议保留奶油背景和陶土品牌色，关键读数/输入可用较浅的 `WarmSurfaceSoft #F9F4ED`，普通设置改为分组列表；浅绿留给正常状态，次级说明不再用绿色承载。统一页面边距与卡片圆角，减少图表页独有的边框加阴影叠加。重要数值可比较系统无衬线数字与现有 Caprasimo 的识别速度，后者适合作点缀，是否更换需看真实读数样张。

### 10. 趋势读图门槛仍可降低【代码确认】

坐标和参考线文字只有 9–10sp；参考文字 `#C0B6A5` 在卡片上约 **1.50:1**。两条曲线用橙/绿区分，但图例都用圆点，同类线型对色觉差异用户帮助有限。现有逐点文字浏览是有价值的，应保留。

位置：`ui/history/TrendChart.kt:618–622,649,749,776,832,858`。

建议：坐标和参考值提高字号与对比度；曲线增加实/虚线或不同点形，并同步图例；参考线区分于数据线。把“横轴按真实时间排列”等长说明收进帮助入口，默认只保留“点选查看，双指缩放”等与实际手势一致的短提示。本次无数据，未验证手势和曲线布局。

### 11. 设置入口未明确告知包含药品管理【实机观察】

“提醒设置”副标题只有“晨间/晚间测量提醒和提醒时间”，实际上下级还包含药品维护、每日服药时间和日历同步。用户要找药品管理时不容易从设置首页判断入口。

证据：[设置](07-settings.png)、[提醒设置](08-reminders.png)。建议改成“测量与用药提醒”，副标题包含药品；若内容继续增加，将药品与提醒分别组织。设置页“应用说明与更新说明”也可缩为“关于与帮助”，避免副标题末尾孤字换行。

## 配色实施参考

| 用途 | 当前问题 | 建议 |
|---|---|---|
| 页面背景 | 风格明确 | 保留 #F5EAD8 |
| 主文字 | 清晰 | 保留 #201E1D |
| 关键标签、说明 | 灰褐偏淡 | 关键标签用 onSurface；说明考虑 #645C50 |
| 小字实心选项 | 白/橙 3.40:1 | 使用更深橙与浅字配对，或浅橙底深棕字 |
| 卡片 | 大面积沙色重量相近 | 关键内容尝试 #F9F4ED，减少容器嵌套 |
| 状态 | 绿色泛用、红点表示备注 | 正常绿、警示橙、高风险红，均配文本/图形 |
| 深色模式 | 固定深棕色残留 | 为每个容器匹配主题文字色，统一语义 token |

对比度按 WCAG 相对亮度公式计算，普通文字以 4.5:1、大字以 3:1 为审查参考；这是可读性基准，不声称整个 Android 应用完成 WCAG 合规评估。[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)。交互区域建议保留至少 48dp；Compose 可能自动扩展点击区域，不能仅凭 44dp 的视觉高度认定实际触控不合格。[Android Compose 默认无障碍行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。
