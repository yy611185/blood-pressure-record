## 一、验证原则与真实性纪律

1. **风险导向分层验证**：优先覆盖本次实际代码改动涉及的核心界面、高风险交互（中老年高频录入、软键盘遮挡、大字折行、隐私导出一致性）及待冻结参数；**不进行无必要的重复构建、全量测试或漫无目的的模拟器轮询**。
2. **严禁凭源码推测宣称通过**：任何因缺少真实硬件、厂商系统、打印设备或第三方应用而未能实际目视测试的条目，验收状态**必须明确填写为 `未验证`**，绝不得根据代码逻辑推断填写「通过」。
3. **系统环境严格区分**：涉及华为生态测试时，必须明确区分**支持运行 Android APK 的 HarmonyOS 环境（如 HarmonyOS 2–4）**与**不兼容 Android 应用的系统环境（如纯血 HarmonyOS NEXT）**；本应用为原生 Android 应用，仅在兼容 Android 应用的环境中验证。
4. **最小修补原则**：验证阶段以真实源码与已确认设计决策为基线，不提前盲改色板或布局；仅针对真机实测确认的具体缺陷开展最小范围修补与定向复验。
